# Respect Talk AI — 対話支援・会話記録・議事録

無料ローカル生成AIとルールベースの短い耳元提案を備えた、iPhone縦画面向けの静的PWAです。既存の音声診断、SpeechRecognition、SpeechSynthesis、GitHub Pages構成を維持しています。有料API・APIキーは不要です。

## 使い方

1. iOSの設定でBluetoothイヤホンを接続し、出力先を確認します。「イヤホン音声テスト」で確認してください。WebアプリからBluetoothの出力先を指定・保証することはできません。
2. 必要なら「生成AIモデルを準備」を押します。初回のみ約400MBを明示的に取得します。未準備・失敗でも `coach.js` が動きます。
3. 録音ON/OFFと「次の実発言の話者」を選び「● 対話開始」を押します。経過時間、実発言、AI判断、耳元提案を表示します。
4. 「私が話す」でAI読み上げを止め、次の話者を私に切り替えます。相手が話すときは話者を相手に戻してください。1台のマイクで自動話者分離はしていません。
5. 「■ 対話終了」で認識・支援・録音を停止し、セッションを端末内に自動保存します。会話履歴で話者変更、文章修正、削除、実発言の補記ができます。読み上げと重なった認識結果は確認待ちです。実発言として確定するか、AI音声として除外してください。
6. 「要点だけ / 標準要約 / 詳細議事録」を選び「議事録を作成」。タイトル・参加者を編集し、変更後は「保存」を押します。保存一覧から再表示・削除できます。削除時は会話と録音を一緒に消します。

## データ分離と文脈

`ConversationSession` は開始から終了まで、実発言を `conversationSession`（id / timestamp / speaker / text / confirmed）、AI提案を `assistantSuggestions` に分離します。提案を実発言へ自動コピーしません。AIの回答をユーザーが本当に口に出したときだけ、認識または実発言補記により記録します。

AIへ渡す文脈は実発言のみ、直近20件・最大4000文字です。全履歴はセッションに残ります。モデル未準備時も朝食→寝坊などの文脈をルールへ渡します。手動解析テストは実発言を作りません。確認待ちの重複結果・未確定認識は議事録にもAI文脈にも入れません。話者の既定値は相手の推定（未確認表示）で、ワンタップで相手/私へ修正できます。

## 短い応答とローカルAI

Transformers.js **3.7.3**、`onnx-community/Qwen2.5-0.5B-Instruct` **q4** を維持しています。専用のmodule Workerでモデルを読み込み、WebGPU（Workerで利用可能な場合）またはWASMで推論します。実発言の文脈を含め、相槌・共感・驚き・共有・質問・深掘り・軽いユーモア・励まし・アイデア・提案・聞くだけから選択します。

通常5～25文字、最大35文字の口語を指示し、講義形式の候補はルール応答に戻します。まず即時のルール候補を画面表示し、ローカル推論は1200msの応答予算で待ちます。間に合わなければそのターンはルールの短い候補だけを読みます。相槌と遅れた本回答の二重読み上げは行いません。時間切れの推論はWorker内で完了する場合がありますが、結果を後から読み上げません。推論は直列化し、終了・話者変更・履歴編集で古い結果を無効にします。「聞くだけ」なら読み上げません。

iPhone Safariでのモデル展開、GPU利用、生成速度、メモリ容量は端末依存です。1200msは待機上限の方針であり、音声認識やBluetoothを含む応答時間の保証ではありません。Worker自体が使えない場合もルールへ戻します。

## 録音と読み上げの競合

録音は `getUserMedia` のマイクストリームを `MediaRecorder` へ渡し、対応MIMEを `audio/mp4` → Opus/WebM → ブラウザ既定の順に選びます。録音ONは対話開始前に選択し、録音中は **🔴 録音中** を表示します。生成音声を録音ストリームへ接続しません。エコーキャンセルとノイズ抑制を要求しますが、端末の対応に依存します。

AI読み上げを依頼する前に録音を一時停止し、終了後350msの保護時間を経て再開します。除外した時間帯を `recordingGaps` と履歴画面に表示します。「私が話す」はTTSを止め、録音を直ちに再開します。

音声認識は読み上げのために一律停止しません。読み上げ中・停止直後・最近の提案に似た認識結果は、捨てずに `pendingUtterances` に隔離し、実発言かAI音声かをユーザーが確定します。未確定の途中認識も終了時に確認待ちに残します。

**完全な音声分離は実装済みと主張しません。** iOS/Safariは任意の入力・出力経路、Bluetooth遅延、システム側の音声認識停止をWebアプリで制御できません。音漏れが誤認識される可能性や、AI読み上げの録音除外区間で実音声を失う可能性があります。除外区間のテキストは認識できた範囲で確認待ちに保持し、実発言の補記も用意しています。音漏れと人間の声の完全な識別、途切れない録音、完全な同時認識・TTSは保証できません。iPhone実機/Bluetoothでの確認が必要です。

## 議事録・要約

議事録入力は `minutesInput()` が日時・参加者・実発言だけを明示的に取り出します。`assistantSuggestions` と確認待ちの発言を入力へ含めません。

準備済みの無料ローカルAIは、実発言IDを選ぶ「証拠に基づく抽出要約」を行います。出力には実発言の引用だけを使い、モデルが作った架空の発言を追加しません。存在しないIDは拒否し、決定事項は明示的な決定・合意の発言だけに限定します。分類の誤りや否定表現の見落としはあり得るため内容を確認してください。決定のない雑談は「該当する発言なし（未確認）」とします。

- 要点だけ：最大3件の要点、重要事項・決定・アイデア・次の確認。全文なし。
- 標準要約：最大5件の選択要約＋会話全文。
- 詳細議事録：最大10件の選択要約＋会話全文。

AI未準備・失敗・処理中・30秒超過・入力が12000文字超の場合は、実発言からの抽出へ戻し、方式を表示します。長いセッションでも全文は保持します。内容や参加者を修正すると既存議事録を無効化し、再生成を要求します。自由作文の要約ではなく、誤った決定や発言を混ぜない抽出方式です。

## 保存と外部通信

会話・提案・確認待ち・議事録・録音Blobは、同一端末/同一オリジンの **IndexedDB** (`respect-talk-sessions`) に保存します。アプリから外部AI APIへ会話・録音を送信しません。アカウント、同期サーバー、有料APIは使いません。保存失敗時はエラーを表示し、画面の記録を保持します。編集後は再保存が必要です。容量不足、プライベートモード、ブラウザデータ消去、OSのストレージ回収などによる消失は保証できません。

**SpeechRecognitionの完全な端末内処理は保証できません。** ブラウザ/OS/設定次第でベンダーのサーバーへ音声を送る場合があります。SpeechSynthesisも選択された音声とOSに依存します。

ページ取得は静的ホスト、モデルを明示的に準備する際はjsDelivr/Hugging Face（CDNへのリダイレクトを含む）へ通信します。モデル/ライブラリの通信には会話内容を含めません。Service Workerはアプリ静的資産をキャッシュし、モデル未準備のオフラインでもルール解析・保存一覧を利用できます。音声認識のオフライン可否はブラウザ依存です。

## レスポンス時間の測定

診断画面に次の値と実測平均（件数付き）を表示します。

- 認識：最初のinterim文字表示からfinal確定まで。音声の開始時刻やベンダー内部の認識時間は取得できないため、完全な音声→文字起こし時間ではありません。
- AI判断：ルール/ローカルAIの判断待ちにかかった時間（fallback待機を含む）。
- 読み上げ開始：SpeechSynthesis依頼から`onstart`まで。
- 合計：最初の文字表示から`onstart`まで。
- 平均：現在の対話で`onstart`が届いた自動提案の合計時間の平均。新規対話でリセットします。読み上げOFF/失敗/手動再生は合計の測定対象外です。

`onstart`は端末側のイベントです。Bluetoothイヤホンで実際に音が出た時刻や話者の発話開始からの遅延を保証しません。iPhone実機では同じフレーズを複数回試し、ローカル/ルールモード・録音ON/OFFを診断スイッチで比較してください。

## 開発・テスト・GitHub Pages

```bash
npm ci
npm test
npm run lint
npm run build
python3 -m http.server 8000 --directory dist
```

既存の `npx serve dist` も使用できます。ブラウザ統合テストは以下で実行します。

```bash
npx playwright install chromium
npm run build
npm run test:browser
# システムChromiumを使う場合
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

単体テストは実発言/AI分離、編集、要約、失敗/遅延fallback、録音状態などを検証します。ブラウザテストは390px画面、開始/終了、履歴編集、IndexedDB再読み込み、録音、競合、削除、3種の要約、古いAI結果の無効化を検証します。音声・MediaRecorder・ローカルモデルは模擬です。別途、実Chromiumの手動解析、Worker起動、PWAのオフライン資産を検証します。**これらはiPhone Safari実機や実モデルの速度検証ではありません。**

GitHub Pagesでは従来どおりmainブランチのルートを公開できます。今回の変更は別ブランチでPRを作成し、mainへ直接変更しません。SafariではHTTPSで開き、共有メニューから「ホーム画面に追加」を選択してください。更新後は古いタブ/PWAを閉じ、再度開いて新しいService Workerを有効にします。

実機受け入れ確認：マイク許可→イヤホン音声テスト→手入力→実会話→私の話者切替→読み上げ中の確認待ち→録音除外表示→停止→再読み込み保存復元→議事録でAI提案が除外されること→保存削除を確認してください。iOSが画面ロック/バックグラウンド時に停止させる場合があるため、前面で使い、終了後の記録を確認してください。
